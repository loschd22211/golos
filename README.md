# 🎙 Голос

**Нажали кнопку — говорите. Текст сразу появляется там, где стоит курсор.**

Маленькая плашка в углу экрана, без окон и вкладок: клик по микрофону, говорите
обычным темпом — слова вставляются в активное поле по мере речи (кусками по
1–2 секунды), а не после того, как вы остановились. Русские и английские слова
можно мешать: «сделай commit и push в GitHub» так и запишется.

Распознавание идёт **на вашем компьютере** (faster-whisper), без интернета и без
отправки голоса в облако. Интернет нужен один раз — скачать модель.

## Что умеет

| | |
|---|---|
| 🎤 **Одна кнопка** | клик — запись, клик — стоп. Ничего настраивать не обязательно |
| ⚡ **Текст по ходу речи** | куски вставляются каждые 1–2 секунды, не дожидаясь конца |
| 📍 **Прямо у курсора** | окно запоминается в момент старта: переключение вкладок не уводит текст |
| 🌍 **Русский + английские термины** | «сделай commit и push» пишется как сказано; иероглифы не появляются |
| 🪟 **Стекло** | плашка 348×96 без рамки — полупрозрачная, со скруглёнными углами и размытием фона |
| 🛑 **Ошибки видно сразу** | красный текст в плашке, значок «!» и журнал по клику |
| 🧠 **Whisper офлайн** | модель подбирается сама: `medium` на видеокарте, `small` на процессоре |
| ⌨️ **Горячая клавиша** | `Ctrl+Alt+Space` — то же самое, не трогая мышку |
| 🔔 **Трей** | иконка с индикатором записи, меню, автозапуск |

## Установка (Windows 10/11)

1. Установите [Python 3.10–3.12](https://www.python.org/downloads/windows/),
   отметив галочку **`Add python.exe to PATH`**.
2. Скачайте проект в любую папку, например `C:\Users\user\Downloads\golos`.
3. Запустите **`run.bat`** — он сам создаст окружение, поставит зависимости,
   сделает ярлык «Голос» на рабочем столе и запустит программу (первый раз
   несколько минут).

Дальше консоль не нужна: программу запускает **ярлык «Голос»** (рабочий стол или
«Пуск») либо двойной щелчок по **`golos.vbs`** в папке программы — оба варианта
без окна консоли. Автозапуск при входе в Windows включён по умолчанию
(снимается галочкой «Запускать с Windows» в настройках).

Обновление и запуск в дальнейшем:

```powershell
cd C:\Users\user\Downloads\golos
.\update.bat
```

`update.bat` сам остановит запущенную программу, переключится на `main`, сделает
`git pull` и запустит заново. Это важно: если рабочая копия осталась на старой
ветке, `git pull` пишет `Already up to date`, а код внутри — старый
(диагностика покажет «код отстаёт от main»).

Вручную то же самое:

```powershell
git checkout main
git pull
.\run.bat
```

| Файл | Что делает |
|---|---|
| **`golos.vbs`** | запуск без окна консоли (двойной щелчок) |
| **`run.bat`** | установка (если нужно) + запуск |
| `run.bat --make-shortcut` | пересоздать ярлык «Голос» |
| **`update.bat`** | обновить код из `main` и перезапустить (если `git pull` «ничего не находит») |
| `run.bat --debug` | запуск с консолью: видно каждую ошибку |
| `install.bat` | только установка + ярлык на рабочем столе |
| `doctor.bat` | диагностика в терминале: запись, модель, распознавание, вставка |

Первый раз при диктовке скачается модель (`small` ≈ 480 МБ). Дальше интернет не
нужен.

## Как пользоваться

1. Запустите ярлык «Голос» (или `golos.vbs`) — внизу справа появляется плашка
   с микрофоном.
2. Поставьте курсор в любое поле: браузер, Word, Telegram, VS Code, поиск Windows.
3. Нажмите **кнопку микрофона** на плашке (или `Ctrl+Alt+Space`).
4. Говорите. Через 1–2 секунды текст начинает появляться у курсора, дальше —
   дописывается по мере речи.
5. Нажмите кнопку ещё раз — запись остановится, последний кусок допишется.

`Esc` во время записи — отменить и ничего не вставлять.

Плашка показывает состояние:

| Цвет | Значение |
|---|---|
| 🔵 синяя полоса, «Нажмите и говорите» | готов |
| 🔴 красная, кольцо пульсирует | слушаю, внизу уровень микрофона |
| 🟠 оранжевая, «Досказываю…» | дописываю последний кусок |
| 🔴 красный текст + «!» | ошибка, клик по «!» открывает журнал |

Правый клик по плашке — меню: **Настройки**, **Открыть журнал**, **Выход**.
Крестик скрывает плашку в трей, иконка в трее возвращает её обратно.

## Настройки

Правый клик → «Настройки…». Всё применяется сразу.

* **Модель** — `tiny` / `base` / `small` (по умолчанию) / `medium` / `large-v3`;
* **Язык** — «Русский (English слова — латиницей)» по умолчанию, «Только
  английский»; режимы «Смешанная речь» и «Авто» оставлены для экспериментов: на
  коротких кусках они ошибаются и подмешивают иероглифы;
* **Вставка** — буфер + `Ctrl+V` (быстро) или посимвольно;
* **Микрофон** — список устройств ввода;
* **Прозрачность** — от «Непрозрачная» до «Лёгкая 75%»;
* **Горячая клавиша**, **звуки**, **автозапуск с Windows** (включён по
  умолчанию), **права администратора**, кнопка **«Ярлык на рабочий стол»**.

Остальное — в `%APPDATA%\Golos\config.json`, в том числе:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `streaming` | `true` | вставлять текст по ходу речи |
| `stream_step` | `0.35` | как часто проверять новый звук, сек |
| `min_chunk_seconds` | `0.8` | минимум звука для очередного куска |
| `hold_back_seconds` | `0.3` | сколько придерживать, чтобы не разрезать слово |
| `force_commit_seconds` | `2.5` | если паузы нет — вставить всё, кроме последнего слова |
| `model` | `auto` | `auto` — medium на видеокарте, small на процессоре |
| `beam_size` | `3` | качество/скорость распознавания |
| `language` | `ru` | `ru` — русский с английскими терминами; `en` — только английский; `ru+en` / `auto` — по кускам (риск иероглифов) |
| `overlay_opacity` | `0.94` | прозрачность плашки (0.55–1.0) |
| `normalize_audio` | `true` | подтягивать тихую речь до нормальной громкости |
| `skip_non_speech` | `true` | не отправлять в модель музыку, гул и ровный шум |
| `word_confidence` | `0.35` | минимальная уверенность модели в слове, 0–0.95 |
| `pin_target` | `true` | держать окно-получатель до конца диктовки |
| `autostart` | `true` | запускать «Голос» при входе в Windows |

Хотите «всё и сразу после остановки», как раньше? Поставьте `"streaming": false`.

Таблица моделей:

| Модель | Загрузка | Когда выбирать |
|---|---|---|
| `tiny` | ~75 МБ | очень старый ноутбук, короткие команды |
| `base` | ~145 МБ | быстро, но ошибок больше |
| **`small`** | ~480 МБ | **по умолчанию**: быстрый старт и нормальная точность |
| `medium` | ~1.5 ГБ | точнее, но первая загрузка 10–20 с |
| `large-v3` | ~3 ГБ | максимум точности, желательно видеокарта NVIDIA |

## Диагностика в терминале

Одна команда показывает по шагам, что работает, а что нет:

```powershell
cd C:\Users\user\Downloads\golos
.\doctor.bat
```

Скрипт проверяет: Python и файлы проекта, настройки, пакеты, микрофоны,
горячую клавишу, буфер обмена, **запись с микрофона**, загрузку модели,
распознавание, поведение потоковой вставки и последние строки журнала.

Перед записью он печатает образец — прочитайте его вслух:

```
«Проверка связи, один, два, три. Сделай commit и push в GitHub.»
```

После распознавания показывает текст рядом с образцом и **похожесть в
процентах**. Если она ниже 50 %, значит речь теряется: пришлите этот вывод,
по нему видно, где именно (микрофон, модель, язык). По каждому пункту печатает `[ OK ]`,
`[ ?? ]` или `[БЕДА]`, в конце — список проблем. Отчёт дублируется в
`diagnostic.txt`.

Полезные варианты:

```powershell
.\doctor.bat --fix        # привести config.json к рабочим значениям (с бэкапом)
.\doctor.bat --record 8   # писать микрофон 8 секунд вместо 5
.\doctor.bat --device 8   # проверить другой микрофон из списка
.\doctor.ps1 -Fix         # то же самое из PowerShell
.venv\Scripts\python.exe -m golos.diagnose --no-record   # без записи
```

Что означают частые сообщения:

| Сообщение | Что делать |
|---|---|
| `[БЕДА] нет пакета …` | `run.bat` не доустановил зависимости — запустите `install.bat` |
| `[БЕДА] микрофон молчит (тишина)` | Параметры → Конфиденциальность → Микрофон → разрешить приложениям |
| `[БЕДА] модель вернула пустой текст` | проверьте микрофон и язык (должен быть `ru`) |
| `[БЕДА] не удалось назначить ctrl+alt+space` | сочетание занято — смените в настройках плашки |
| `[ ?? ] слов до порога нет` | нормально: сработает принудительная вставка через 2.5 с |
| `[ ?? ] видеокарта есть, но не хватает cublas64_12.dll` | быстрый путь: `python -m pip install nvidia-cublas-cu12 nvidia-cudnn-cu12` (или `install.bat` заново) |
| `[ ?? ] запущено без прав администратора` | в админские окна (часто браузер) текст не вставится — см. ниже |
| `[ ?? ] фильтр тишины выключен` | верните `"silence_threshold": 0.004` — иначе медленнее и больше выдумок |
| `[ ?? ] код отстаёт от main` | запустите `update.bat` — иначе исправления не подхватятся |
| `[ ?? ] модель small ещё не скачана` | первый запуск скачает ~470 МБ: это минуты, нужен интернет |
| `… модель small: идёт 40 c` | так диагностика показывает, что не зависла, а грузит модель |
| `[ ?? ] чужое активное окно не найдено` | щёлкните в поле, куда нужен текст, и запустите диагностику снова |

## Если текст не появляется

1. Плашка показывает состояние: серая строка `слушаю…` и «вставлено: …» после
   каждой вставки. Если `вставлено:` не появляется — смотрите пункт про
   потоковую вставку в `doctor.bat`.
2. **Окно-получатель от администратора — главная причина «текст есть, а в поле пусто».**
   Windows не пропускает нажатия клавиш из программы с обычными правами в окно,
   запущенное от имени администратора. Чаще всего так запущен браузер — тогда
   распознавание работает, плашка пишет «вставлено», а в поле ничего нет.

   Начиная с версии 1.2 «Голос» сам просит права при запуске: при первом
   `run.bat` Windows покажет запрос UAC — нажмите **«Да»**. Если отказались
   (или включён автозапуск, где UAC не спрашивается), воспользуйтесь меню:
   правый клик по иконке микрофона в трее → **«Перезапустить от администратора»**.

   Настройки этого поведения:

   | Что | Как |
   |---|---|
   | Не спрашивать права никогда | `"run_as_admin": false` в `config.json` или `run.bat`/`golos_app.py --no-admin` |
   | Галочка в интерфейсе | правый клик по плашке → «Настройки» → «Права администратора» |
   | Уже запущено, права нужны сейчас | трей → «Перезапустить от администратора» |
   | Просто убрать лишние права у браузера | ярлык → Свойства → Дополнительно → снять «Запуск от имени администратора» |

   Если права есть, но вставки всё равно нет, в журнале будет строка
   `Вставка в окно: «…» (chrome.exe)`, а при блокировке — не «вставлено»,
   а понятная ошибка на плашке.
3. **Способ вставки.** Правый клик по плашке → «Настройки» → «Вставка» →
   «Посимвольно» — помогает там, где буфер обмена не срабатывает.
4. **Текст ушёл в другую вкладку/окно.** С 1.4 окно-получатель закрепляется
   в момент старта диктовки: переключение вкладок во время речи текст не
   уводит. Окно запоминается то, что было активным **в момент старта** —
   поэтому сначала поставьте курсор, потом запускайте запись.
   Смотрите также строку
   `Вставка в окно: …`: там написано, какое окно получило текст и с какими
   правами. Если это `«Голос» (pythonw.exe)` — версия старше 1.2.1,
   обновитесь через `update.bat`.
5. **Быстрый обходной путь без потокового режима.** В `%APPDATA%\Golos\config.json`
   поставьте `"streaming": false` — текст вставится после остановки записи
   (этот путь самый стабильный).

## Файлы и приватность

```
%APPDATA%\Golos\config.json   настройки
%APPDATA%\Golos\golos.log     журнал (ротация 1 МБ × 3)
%APPDATA%\Golos\history.txt   история диктовок (можно отключить)
%APPDATA%\Golos\models\       модели Whisper
```

Аудио не пишется на диск и никуда не отправляется: всё обрабатывается в памяти.
Единственный сетевой запрос — скачивание модели при первом использовании.

## Что нового в 1.6.3

**Запись в родной частоте микрофона.** Раньше «Голос» просил у драйвера сразу
16 кГц. Windows соглашалась и пересэмплировала звук своим фильтром (особенно
через хост-API MME) — речь становилась глухой, и модель выдавала «Алло!» вместо
фразы. Теперь пишем в частоте устройства (обычно 48 кГц), на Windows используем
WASAPI, а к 16 кГц приводим сами, поблочно (без лишней нагрузки на процессор).

**Диагностика показывает, что реально записалось:**

* `RMS`, `пик`, доля перегруженных кадров;
* предупреждение `в записи не слышно речи — ровный шум, музыка или тишина`
  (это не «модель плохая», а не тот микрофон);
* запись сохраняется в `%APPDATA%\Golos\test-audio.wav` — её можно послушать
  и убедиться, что в микрофон попадает именно ваш голос;
* `doctor.bat --device 8` проверяет другой микрофон, не меняя настройки;
* если «целью вставки» оказалась сама плашка «Голос» (другой экземпляр), это
  теперь так и написано: текст в плашку не печатается.

## Что нового в 1.6.2

**Пустой текст на живой речи.** Диагностика показывала «модель вернула пустой
текст» и «модель не вернула сегментов на куске речи»: VAD и пороги уверенности
выбрасывали тихую или шумную запись целиком. Теперь, если модель вернула пустоту,
а звук в куске явно есть (пик > 0.01), кусок распознаётся **повторно без VAD и
порогов**. Пусть лучше будет текст с огрехами, чем пропавшая фраза. Тишина и
музыка по-прежнему не отправляются в модель.

**Диагностика показывает, где теряется скорость и точность:**

* в «Настройках» теперь видны `device` и `compute_type` — видно, что считает
  процессор, хотя видеокарта есть;
* новый раздел «Скорость»: `[ ?? ] видеокарта работает, но в настройках выбран
  процессор`, `[ ?? ] модель base путает слова`;
* `[ ?? ] микрофон перегружен (пик почти 1.0)` — перегрузка входа превращает
  речь в шум, её видно по пику;
* `doctor.bat --fix` на рабочей видеокарте ставит `device: auto` и модель
  `small` вместо `base`/`tiny`.

## Что нового в 1.6.1

**Возврат к жёсткому русскому языку — иероглифы убраны.** В 1.6.0 язык по
умолчанию определялся по каждому куску («смешанная речь»), и на коротких кусках
Whisper «слышал» японский: в тексте появлялись «もう、ガ サ», «汉字» и прочие
чужие письменности вместо сказанного. Что сделано:

* по умолчанию снова `"language": "ru"`: язык задаётся жёстко, английские
  термины при этом пишутся латиницей («сделай commit и push» — как сказано);
* сохранённый ``"ru+en"``/``"auto"`` от 1.6.0 миграция переводит на ``"ru"``;
* если режим «по кускам» всё-таки включён, а модель определила не русский и не
  английский, кусок **переспрашивается по-русски**;
* иероглифы, кана и хангыль вырезаются из текста до вставки, а кусок, состоящий
  из них хотя бы наполовину, считается галлюцинацией и не вставляется;
* «язык сеанса» больше не может закрепиться на японском/китайском.

## Что нового в 1.6.0

**Остановили запись — текст появляется сразу.** Финальный проход модели больше
не держит интерфейс: звук снимается и микрофон выключается мгновенно, остаток
дораспознаётся в фоне, а горячая клавиша продолжает работать. Раньше плашка
«Распознаю…» висела ~20 секунд, и второй раз клавиша не отвечала.

**Одна фраза больше не вставляется десятками раз.** Кусок, который повторяет
конец уже вставленного текста, отбрасывается целиком (`«Понимаешь.» ×50` из
журнала — ровно этот случай). Короткая фраза, повторяющаяся через раз в окне
последних 12 вставок, тоже не вставляется. Хвост старого промпта
(«Смешанная русская и английская речь…») добавлен в чёрный список.

> В 1.6.0 здесь был режим `"ru+en"` по умолчанию (язык по каждому куску). Он
> давал иероглифы вместо русской речи — в 1.6.1 основной режим снова `"ru"`,
> см. раздел выше.

**Запуск двойным щелчком, без консоли.** Ярлык «Голос» на рабочем столе и в
«Пуске» создаётся установщиком и автоматически при первом графическом запуске
(кнопка «Ярлык на рабочий стол» — в настройках плашки, `run.bat --make-shortcut` —
в консоли). Из папки программы запускает `golos.vbs` — тоже без окна консоли.
Автозапуск при входе в Windows включён по умолчанию и снимается галочкой
«Запускать с Windows».

**Текст больше не уходит в собственную плашку.** Целью вставки никогда не
выбирается окно `pythonw.exe` / «Голос»; если чужого окна нет, в журнале
честное «Окно-получатель неизвестно» вместо ложного «вставлено».

**CUDA: `cublas64_12.dll` больше не отправляет на процессор.** Библиотеки из
pip-пакетов `nvidia-cublas-cu12` / `nvidia-cudnn-cu12` ищутся в нескольких
раскладках, подключаются через `os.add_dll_directory`, и только если их правда
нет — откат на CPU с понятной подсказкой. `doctor.bat` показывает, есть ли
ярлык, автозапуск и библиотеки CUDA.

## Что нового в 1.5.1

**Убраны слова, которых вы не говорили.** В журнале и на экране появлялись
«Спокойная музыка», «Поп», «Ну это было» — это не ошибка распознавания вашей
речи, а галлюцинации Whisper на музыке, гуле и ровном шуме. Четыре
независимых фильтра:

1. **«Это вообще речь?»** Кусок с ровной громкостью и без речевых пауз
   (музыка-подушка, вентилятор, наводка) в модель **не отправляется** вовсе.
   У речи огибающая «дышит» — на слогах и паузах; у музыки и гула она плоская.
   Отключается `"skip_non_speech": false`.
2. **Уверенность в каждом слове.** faster-whisper отдаёт вероятность для
   каждого слова. Слова ниже `word_confidence` (0.35) не вставляются — именно
   так в текст попадали «додуманные» слова на фоне музыки.
3. **Музыкальные фантомы в чёрном списке:** «спокойная музыка», «играет
   музыка», «поп», «рок», «джаз», «мелодия», «трек» и подобные — плюс правило
   «куплет из одного-двух таких слов = не речь».
4. **VAD строже:** порог 0.6 вместо 0.5 и минимальная длительность речи 200 мс —
   музыка перестаёт проходить как речь ещё до модели.

Плюс мягче порог отсева сегментов (`no_speech_prob > 0.45` при
`avg_logprob < -0.6`). В журнале видно, что именно отброшено и почему:
`Поток: отброшено неуверенных слов 2 (Поп, Если)` и
`Поток: 1.4 c — похоже на музыку/шум … — пропущено`.
`doctor.bat` проверяет оба новых фильтра отдельными пунктами.

## Что нового в 1.5

Переделал то, что мешало больше всего: вид плашки, качество текста и скорость.

* **Серый квадрат убран по-настоящему.** Выяснилось, что акрил
  (`SetWindowCompositionAttribute`) в Windows **игнорирует форму окна** и
  закрашивает весь прямоугольник — со скруглением он несовместим в принципе,
  отсюда и квадрат. Акрил выброшен целиком. Теперь фон окна — «ключевой»
  цвет (`-transparentcolor`), который система не рисует вообще: видна только
  скруглённая панель, края сглажены, ничего вокруг нет. Если система не умеет
  прозрачный фон — окно красится в цвет панели, и плашка выглядит обычной.
* **Модель подбирается под компьютер.** По умолчанию в настройках `auto`:
  на видеокарте берётся `medium` (русский он знает заметно лучше, GPU его
  держит), на процессоре — `small`. Если `medium` не влезет в видеопамять,
  программа сама откатится на `small` **на видеокарте**, а не на процессор.
* **Тихая речь больше не теряется.** С тихим микрофоном (пик 0.02–0.07 —
  это был твой случай) Whisper слышал шум и выдавал пустой текст. Теперь тихие
  куски подтягиваются по громкости до нормального уровня (не более чем в 12
  раз, чтобы не вылез шум комнаты) — и в потоковом режиме, и при обычной записи.
* **Меньше выдумок на паузах.** В потоковом режиме включён
  `hallucination_silence_threshold=2.0`: если модель «додумывает» фразу у
  длинной паузы, этот кусок пропускается и распознавание идёт дальше.
* **Диагностика показывает конкретную модель** (`модель auto → medium`,
  объём загрузки, что реально загрузилось) вместо слова `auto`.
* **Настройки не перезаписываются зря:** `doctor --fix` больше не меняет
  выбранную модель, если она рабочая.

## Что нового в 1.4.1

* **Убран «серый квадрат» вокруг плашки.** Причина была двойная: скругление
  окна молча не применялось (ctypes обрезал HANDLE региона до 32 бит, и
  `SetWindowRgn` получал мусор), а размытие фона (акрил) красит **весь
  прямоугольник** окна — вот и выходил серый прямоугольник с плашкой внутри.
  Теперь: правильные прототипы WinAPI, повторная попытка после появления окна
  на экране, а если скругление всё-таки не удалось — включается прозрачность
  по ключевому цвету и **размытие не включается вообще**.
* **Размытие фона по умолчанию выключено.** Оно включается галочкой
  «Размытие фона» в настройках и только когда углы реально срезаны. Прежние
  конфиги (1.4.0) переводятся автоматически.
* **Панель плотнее и контрастнее** — без акрила она выглядит как обычное
  тёмное стекло, а не выцветший прямоугольник.
* В журнал пишется строка `Вид плашки: скругление=True (регион=True) …` —
  сразу видно, применилось ли скругление на вашей системе.

## Что нового в 1.4

* **Стеклянная плашка.** Полупрозрачная панель со скруглёнными углами: градиент,
  блик и тонкая светлая рамка. Углы скругляются у самого окна
  (`SetWindowRgn`), поэтому нигде не торчат тёмные квадраты, а на Windows 10/11
  включается настоящее **размытие фона** (акрил через
  `SetWindowCompositionAttribute`) — сквозь плашку видно размытые обои.
  Прозрачность и «стекло» переключаются в настройках и применяются сразу.
* **Текст идёт туда, где стоял курсор.** Раньше цель вставки пересчитывалась
  10 раз в секунду: переключился на другую вкладку или окно во время речи —
  и следующие куски уезжали не туда. Теперь окно-получатель **закрепляется**
  в момент старта диктовки и держится до конца: перед каждой вставкой «Голос»
  возвращает фокус именно ему, а после остановки закрепление снимается.
  Работает и с кнопки на плашке, и по `Ctrl+Alt+Space`; сама плашка целью
  стать не может.
* **Язык больше не скачет.** В режиме «Авто» язык определяется один раз за
  диктовку (нужно ≥2 секунд речи и уверенность ≥70%), дальше весь сеанс идёт
  на нём — раньше на кусках по 0.35 с определение прыгало и половина текста
  выходила английской. По умолчанию, как и в 1.3.1, русский.
* **Кнопки и полоса уровня — скруглённые**, в тон стеклу.

## Что нового в 1.3.1

* **Русский язык по умолчанию.** С `"language": "auto"` Whisper на коротких
  кусках (0.35–1 с, из которых состоит поток) принимал русскую речь за
  английскую — в журнале пользователя так и появились «Fiking», «Thank you.»,
  «Ok. It's good.» вместо сказанного. Теперь распознаётся как русский,
  английские термины (`commit`, `push`) при этом остаются латиницей:
  они есть в словаре модели. `doctor.bat --fix` переписывает `"auto"` в `"ru"`;
  вернуть автоопределение можно в настройках.
* **Зацикливания модели больше не попадают в текст.** Whisper «залипает» на
  тишине и шуме и повторяет одно и то же: «Аллоууууууу…», «Приём, приём,
  приём, приём». Такой кусок распознаётся, но не вставляется (а звук при этом
  считается обработанным, поэтому цикл не повторяется).
* **Мусорные значки вычищаются.** В текст проходили служебные символы из
  обучающих данных (`〬`, пометки, эмодзи). Теперь остаются только буквы,
  цифры, обычная пунктуация и полезные знаки (`$ % + ° №`).
* **Диагностика честнее.** Раньше после «критичных проблем не найдено» она
  всё равно писала «нашла проблемы» — вердикт печатался дважды. Теперь итог
  один, от самой диагностики. Проверка микрофона слушает до 3 секунд и
  перестаёт ждать, когда услышала голос; если в записи была тишина, пустой
  текст и «нет сегментов» больше не считаются двумя отдельными поломками.
  Когда видеокарта работает, диагностика подсказывает модель `medium`.
* **`--fix` напоминает перезапустить программу** — настройки читаются при
  старте, работающая плашка их не подхватит.
* **Установка CUDA больше не выглядит зависанием.** Если библиотеки уже
  стоят, `install.ps1` их не перекачивает; если нет — пишет, что это ~1 ГБ и
  5–15 минут, и качает с индикатором прогресса, а не молча.

* **Кнопки в плашке работают.** Крестик и шестерёнка рисовались в одном месте,

* `doctor.bat` проверяет фильтры и подсказывает, как включить видеокарту.

## Что нового в 1.2.1

* **Текст больше не уезжает в саму плашку.** В журнале было видно, что половина

## Что нового в 1.2

* **Текст вставляется в любые окна.** Windows (UIPI) выбрасывает нажатия из
  программы без прав, если окно-получатель запущено от администратора — обычно
  это браузер. Теперь «Голос» при запуске сам просит права (запрос UAC, «Да»),
  в трее есть пункт «Перезапустить от администратора», а в настройках — галочка.
* **Больше нет ложного «вставлено».** Перед вставкой проверяются права
  окна-получателя; если ввод заблокирован, плашка показывает понятную ошибку
  с решением, а в журнал пишется строка `Вставка в окно: «…» (chrome.exe)`.
* `Ctrl+V` отправляется пошагово (модификатор, пауза, клавиша) — браузеры и
  Electron-приложения принимают такое нажатие надёжнее.
* Диагностика проверяет права администратора и объясняет, что с ними не так.
* `run.bat` ждёт завершения запроса UAC и не пугает ложной ошибкой запуска.

## Что нового в 1.1

* Исправлена главная причина «микрофон работает, а текста нет»: при
  непрерывной речи Whisper возвращает один сегмент до самого конца записи, и

## Разработка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
python -m pytest -q          # 364 теста, ~6 секунд
python golos_app.py --debug  # запуск с журналом в консоли
```

Аргументы: `--debug`, `--no-gui` (текст в консоль), `--silent` (только трей),
`--status` (запущен ли, код 0/1), `--config PATH`, `--version`.

```
golos/
  overlay.py      плашка 340×92: кнопка, уровень, ошибки, мини-настройки
  streaming.py    потоковое распознавание + вставка по кускам
  winfocus.py     WS_EX_NOACTIVATE и возврат фокуса (ctypes, без зависимостей)
  app.py          ядро: запись → распознавание → вставка, состояния, статистика
  audio.py        микрофон (sounddevice), снапшоты для потока, обрезка тишины
  transcribe.py   faster-whisper: ленивая загрузка, сегменты с таймингами
  textproc.py     чистка текста: пунктуация, склейка алфавитов, замены
  inject.py       вставка: буфер + Ctrl+V или посимвольно
  hotkeys.py      глобальные клавиши, pretty_hotkey
  tray.py         иконка в трее с индикатором записи
  config.py       настройки и миграция старых конфигов
  system.py       один экземпляр, автозапуск, диалоги ошибок
golos_app.py      точка входа: оверлей + трей + очередь событий
  diagnose.py     диагностика в терминале (doctor.bat)
tests/            364 теста без Windows, микрофона и модели
```

Ядро (`DictationApp`) не зависит от GUI: интерфейс получает события через
`UiBridge`. В тестах подменены звуковая карта, движок Whisper, буфер обмена,
клавиатура и tkinter, поэтому вся логика проверяется на Linux/CI.

## Ограничения

* Только Windows (перехват клавиш, автозапуск, `WS_EX_NOACTIVATE`).
* Потоковый режим — скользящее окно, а не «настоящий» стриминг Whisper: на
  границах кусков возможны шероховатости в пунктуации. Длинные паузы режут текст
  на фрагменты (каждый вставляется отдельно).
* По одному куску за раз: если говорить очень быстро и долго, распознавание может
  немного отставать.
